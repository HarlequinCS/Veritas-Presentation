VERITAS Chapter 1 · Background
Slide 02 - Background

The rise of vibe coding changed how developers meet security.

  • AI-assisted development lets users build full applications from natural-language prompts.
  • This high-level approach often detaches developers from the underlying security architecture.
  • AI tools may reproduce legacy vulnerabilities and insecure patterns from training data.
  • Headless browser simulation can demonstrate flaws visually, not just describe them.

VERITAS Chapter 1 · Problem Statement
Slide 03 - Problem Statement

Four problems that existing tools do not solve.

  • 01High dependency, low confidence. Developers use AI heavily but do not trust the security of generated code.
  • 02Technical reports. Existing security outputs are too complex for non-specialist developers to act on.
  • 03False positives. Frequent inaccurate alerts cause fatigue and erode trust in automation.
  • 04No exploit validation. Developers need to know what is real and exploitable, plus how to fix it.

VERITAS Chapter 1 · Scope
Slide 05 - Project Scope

Operationally bounded, ethically disciplined.

In Scope

  • Hybrid analysis: Black Box (URL) and White Box (source code)
  • Big 5 vulnerabilities derived from the OWASP Top 10
  • Evidence-based validation through screenshots and interaction logs
  • Simulated attacker behaviour and simplified remediation intelligence
  • Evaluation on DVWA, OWASP Juice Shop, and AI-generated test cases

Out of Scope

  • Production environments
  • Non-consensual testing
  • Infrastructure-layer testing (firewalls, port scanning)
  • Destructive exploitation or Denial of Service

VERITAS Chapter 2 · Literature Review
Slide 09 - Traditional Tools and the Gap

SAST and DAST each solve only part of the problem.

SAST - Static Analysis

  • White-box approach with full access to source code
  • Effective early in the SDLC for structural flaws
  • Tends to produce a high rate of false positives
  • Weak at runtime and interaction-driven vulnerabilities

DAST - Dynamic Analysis

  • Black-box approach against a running application
  • Strong for runtime and configuration issues
  • Applied later in the SDLC, when fixes are costlier
  • Often lacks source-level remediation context

VERITAS Summary · Q&A
Slide 12 - Summary & Q&A

Closing the loop from detection to action.

The Problem

AI-dependent developers face technical reports, false positives, and unverified findings. They need exploit validation and simplified remediation.

The Evidence

OWASP, AI-code risk studies, SAST and DAST limitations, simulation research, and AI explanation literature converge toward an integrated solution.

VERITAS connects detection, exploit confirmation, and AI-assisted remediation into one developer-oriented workflow.
